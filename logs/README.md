# 每日日志存档

每个交易日一份独立日志，文件名即**数据日期**（最新交易日收盘日）。由 `dividend_lowvol_score.py` 自动生成，随 GitHub Actions 每交易日北京 16:20 一起提交。

## 当前口径（2026-11-17 起）

评分模型为 ChatGPT 六维 100 分制、34 个子项。单份日志的固定结构：

1. **一、评分总览** — 两只标的的收盘价、综合评分、评级、较前一日变化、数据覆盖率（子项级）
2. **二、六维拆解** — 六个维度各自的权重、得分、覆盖率，以及每个子项的状态（已实现 / 代理 / 待接入）
3. **三、风险预警** — 触发阈值的条目（含「支付率过高」「股息率异常」「折溢价异常」等）
4. **四、横向对比** — 515450 与 563020 的评分排序、差值、逐维度对照
5. **五、指标覆盖与数据源** — 逐项的 live / proxy / missing 状态与缺失原因、代理口径说明
6. **六、数据异常** — 交易日与运行日不一致、抓取失败、缓存异常等；**仅在有异常时出现**
7. **七、口径与免责** — 模型边界、代理假设与免责声明

## 历史日志的引擎代次

| 文件名 | 引擎 | 口径 |
| --- | --- | --- |
| `2026-11-17.md` 起 | 新引擎 `dlv/`（模块化） | 六维 100 分 / 34 子项，覆盖率 89%（515450）、92%（563020） |
| `2026-11-13.md`、`2026-11-16.md` | 旧引擎（单体脚本） | 六维 100 分 / 34 子项，但「盈利与财务质量」15 分整块缺失，覆盖率 85% |

旧日志保留作对照，不做改写；跨代次比较请以各自日志头部标注的覆盖率为准。

## 命名与幂等

- 同一数据日期重复运行会覆盖同一份日志（内容刷新），不会产生重复文件
- 非交易日不会生成新日志；手动触发时若最新交易日与运行日不一致，会在「六、数据异常」中提示
- 历史评分与历史快照分别留存于 `../data/daily_scores.csv` 与 `../data/history/`，日志属于人读版本
- 索引：仓库看板 `docs/index.html` 底部列出最近 12 份日志的直达链接
